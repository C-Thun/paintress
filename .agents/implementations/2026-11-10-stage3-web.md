# 阶段 3：统一 web 进程 + 按需热重载（2026-11-10）

- 范围：`specs/technical-plan.md` 阶段 3，按 operator 提出的「统一进程」方案实现，并采纳调研后的三处关键修正。
- 依赖新增：`chokidar` 6.0.0（MIT）。

## 对 operator 方案的三处修正（调研后）

| 原设想 | 修正 | 理由 |
| --- | --- | --- |
| `attach project agent-pid` + 定时 check PID | **改为连接存活**（attach 保持 socket 连接） | PID 会被内核复用，轮询会误判「还活着」；连接断开由 OS 保证，零轮询零延迟 |
| 仅 HTTP 端口 3316 | **控制面走 Unix socket**（`~/.paintress/web.sock`），端口只给浏览器 | UDS 比 TCP loopback 快约 50%，`0600` 权限天然限制本用户，不受端口占用影响 |
| 边界未提 | **lockfile O_EXCL 单实例锁 + 路径穿越防护** | 防双实例竞态；防 `../` 与符号链接逃逸（任意文件读取） |

补充：浏览器 SSE 连接也计入存活，任一连接存在即不退出；全部空闲后经 idle 宽限期（默认 60s）才关闭。

## 过程中修正

1. **CLI 位置参数错位（冒烟时发现）**：`watch <name> <dir>` 里 `file` 就是 name，代码却用了 `a1`/`a2`，导致永远报用法错误。已修并加回归测试（`watch 参数齐全时进入过程而非报用法`）。
2. `daemonPid()` 在 ESM 里误用 `require`（运行时崩），改为顶部 import。
3. `ServerResponse` 的 `unwatched` 曾用字面量 `true` 导致赋 boolean 报错；补 `detached` 独立响应类型。
