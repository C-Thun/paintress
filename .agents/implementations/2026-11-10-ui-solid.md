# 前端：Solid + Vite（2026-11-10）

- 范围：把 daemon 内嵌的 HTML 页面替换为独立前端应用（operator 指定：纯 SolidJS + Vite，不用 SolidStart）。
- 版本（实测 npm registry，2026-11-10）：
  - `solid-js` **1.9.18**（latest；2.0 仍是 `next`=2.0.0-rc.21，未转正）
  - `vite` **8.3.7**、`vite-plugin-solid` **2.11.15**（peer 声明支持 vite ^8 与 solid-js ^1.7.2）
  - 不引入 `@solidjs/router`：单视图，用 URL query 同步状态即可

## 为什么不用 SolidStart

`@solidjs/start@2.2.2` 的 peerDeps 要求 `solid-js: ^1.9.15`，**不支持 solid-js 2.0**；而 2.0 仍处 RC。且 Start 是 SSR 框架，本地工具只需要 SPA + 本地 HTTP API，SSR/SSG/部署适配器都用不上。

## 关键设计

1. **iframe 隔离**：渲染结果放 iframe，父应用与设计稿的 CSS 互不污染；阶段 4 的点击选中可通过 `postMessage` 接入。
2. **`<base href>` 注入**：渲染页注入 `/files/<project>/<dir>/`，使图像填充等相对路径正确解析。
3. **降级**：未构建前端时 daemon 仍返回精简 HTML 视图，CLI 单独安装也能用。
4. **开发/生产分离**：开发用 `pnpm dev:ui`（3317 代理 3316）；生产用 `pnpm build`（vite 产物由 daemon 托管）。

## 过程中修正

- App.tsx 初版写了假的 `createEffectOn`（空循环 + queueMicrotask），依赖追踪完全没生效；改为 solid 的 `createEffect(on([...], ...))`。
- HTTP 测试原断言 `/` 返回项目列表 HTML；改为 SPA 后语义变了，测试同步改为验证 `/api/*`，路径穿越测试改测 `/files/*` 与 `/render/*`。
