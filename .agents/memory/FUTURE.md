## 路线剩余阶段（未开始，非延期）

### 阶段 4 — 标记、短号与变更高亮

#### 是什么
- 浏览器里点击节点 → 选中高亮（渲染层已给每个节点写入 `data-node-id`，命中检测一行 `closest('[data-node-id]')`）
- 会话级短号：点击分配 `#1` `#2`，MCP 返回 `#1 → <id> (<name>)` 映射；跨会话作废
- 反向高亮：AI 改完一批节点后，渲染器把「本次改动涉及的节点集合」圈出来
- 嵌套选中：按修饰键选父级，或点击后面包屑切换层级

**为什么等**：依赖渲染器稳定后再做，否则渲染改动会反复推翻标记层的坐标假设。

**触发条件**：阶段 3 的渲染保真度稳定（连续两次真实设计稿验收无布局错位）后开工。

### 阶段 5 — MCP 发布与安装规范化

#### 是什么
1. npm 发布 unpinned 包名 `paintress`（registry 实测未占用）
2. 多客户端配置模板写进 README：Claude Desktop / Cursor / VS Code / Codex / pi 各一份
3. 可选：`server.json` 发布到官方 MCP Registry 供发现
4. 文档同时给两条安装路径：`npx paintress mcp`（便捷）与全局安装（稳定，不受启动时网络影响）

**为什么等**：接口还会随阶段 4 变动，过早固化安装文档会反复返工。

**触发条件**：阶段 4 合并、工具名与参数稳定后发布 `0.2.0`。

## 技术债与待评估

### 渲染器未完整实现的规格项

- `mesh_gradient` 填充：当前降级为首个顶点色 + 警告
- `shader` 填充与效果：当前跳过 + 警告
- 弧形椭圆（`startAngle` / `sweepAngle`）：当前按整圆渲染 + 警告
- 环形椭圆（`innerRadius`）：当前按实心椭圆 + 警告
- 多边形圆角：当前忽略
- `strokeAlignment` 的 center/outer：当前按 inner（CSS border）语义
- 图标库：仅 lucide / feather（其余渲染占位框）
- 文字度量：全部交给浏览器，无离线测量能力
- `imports` 跨文件引用：未实现（格式规格里标 TBD，缺实例）

**触发条件**：真实设计稿出现上述特性且影响可读性时，逐项补。

### 查看器 UI 缺口

当前只有「项目列表 → 文件列表 → 渲染页 + 热重载」，缺：
- 缩放 / 平移
- 点击选中与层级树
- 只读属性面板
- 多页面切换（同项目多个设计稿之间的导航）

**触发条件**：阶段 4 开工时一并做（选中与层级树是同一套交互）。

### 测试框架选型偏置

当前用 Vitest（vite 生态），而项目实际只用到 `describe` / `it` / `expect` 三样，Node 22 内置的 `node:test` 完全够用。**11 个直接依赖 / 186 个传递依赖 / 194MB node_modules** 中相当一部分由测试框架带来。

**代价**：迁移约半天（mock 需手写替换，断言风格基本兼容）。
**触发条件**：operator 认为依赖体积或供应链复杂度是问题时执行；否则保持现状。

### watch 扫描深度参数化

当前 `listDesigns` 硬编码 6 层。operator 要求改为：默认 3 层、`--depth N` 可调、上限 6 层，后缀仍只认 `.ptr` / `.pen`。

**触发条件**：下一次触碰 `src/web/registry.ts` 时顺手做（低风险小改动）。
